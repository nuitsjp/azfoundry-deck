# 画面設計のルール

- 画面はコンパクトでミニマルにする。ラベルと操作から分かる説明、手順番号、重複見出し、常設の操作ガイドを追加しない。
- 利用者の判断に必要な対象名、入力制約、失敗理由、再試行、不完全な結果、モックの識別は残す。補助説明やモックの状態操作は必要時だけ開く。
- 読込中・成功・空・エラーは同じ領域内で置き換える。プログレスやエラーのために領域を後挿入し、入力欄・ボタン・一覧を押し下げない。
- 状態表示には必要最小限の高さを確保する。フォント・折り返し・スクロールバーによる位置ずれにも注意し、巨大な空白は作らない。
- フォーカス表示はスクロール領域の端でも欠けない内側の枠を基本とする。太い二重枠を避け、キーボード操作・高コントラスト表示でもフォーカスを識別可能にする。
- ダイアログは状態変化で中央位置や高さを変えない。スクロールは内容領域に限定し、主要操作を見失わせない。1080×720でも簡潔に操作できるようにする。
- 取得中に操作不可の入力は場所を維持して無効化する。進捗不明の取得に架空の割合を出さない。エラー解消時もフォーカスと入力位置を維持する。
- 一覧の主要操作は一覧見出し行の右側に置く。画面全体の操作と混在させない。
- 配置変更時は正常・読込中・空・エラーを切り替え、代表的な画面サイズで入力欄・ボタン・一覧の位置とスクロール位置を検証する。

仕様・合意・検証結果は [プロジェクト定義](../../docs/project.md)、進捗は [PLAN.md](../../PLAN.md) に記録する。
