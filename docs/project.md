### F1. 操作対象の選択とデプロイ一覧

目的: 操作対象とその配下のデプロイを確認できるようにし、後続の参照・変更機能の前提を作る。対象名、モデル名・バージョン、SKU、Capacity、状態を一覧で確認する案とする。デプロイの検索・詳細表示の追加は、F1 の動作確認時に必要性と範囲を決める。

出典: R1・R2・R5。以下は正式版向けのシナリオ案であり、仮実装での実行結果ではない。

| シナリオ ID | 初期条件・入力 | 操作・契機 | 期待結果・観測内容 |
| --- | --- | --- | --- |
| F1-S1 | 起動直後で操作対象が未選択。Tenant ID は省略、または明示する。 | Subscription、Resource Group、Foundry アカウントを順に選ぶ。 | 各選択に対応する次の候補を表示する。アカウント候補は `AIServices` / `OpenAI` に限定する。未選択の間はデプロイ一覧を取得しない。Tenant 省略時は Azure CLI の現在のテナントを使い、複数テナントの Subscription を合算しない。 |
| F1-S2 | アカウントを選択済みで、対象にデプロイがある。 | 一覧を取得する。再取得操作を行う。 | 要求した対象の一覧を表示する。読込中を表示し、数量の欠損は不明と分かる表示にする。 |
| F1-S3 | 下位の選択または一覧が表示済み、もしくは要求が処理中。 | Tenant を変更して再接続するか、Subscription・Resource Group・アカウントを切り替える。 | 影響する下位の選択と表示を解除する。旧要求が後から完了しても、新しい対象のデータとして表示しない。 |
| F1-S4 | Subscription、Resource Group、対象アカウント、またはデプロイの候補が 0 件。 | 該当する一覧を取得する。 | 0 件と分かる状態を表示する。エラーや読込中とは区別し、次の候補がない場合は下位の選択を進めない。 |
| F1-S5 | Azure CLI がない、未ログイン、または権限不足。 | 読取を試みる。 | アプリは起動状態を保ち、失敗と必要な対処を表示する。自動ログインや別スコープへの切替を行わない。 |
| F1-S6 | 一覧取得中に通信障害、API エラー、またはタイムアウトが発生する。 | 失敗を確認し、障害解消後に再取得する。 | 対象の読取失敗と、取得できた診断情報を表示する。別 API やデモに切り替えず、利用者の再取得で結果を更新する。 |
| F1-S7 | モックを明示的に有効化、または無効化して起動する。 | F1-S1〜S6 を確認する。 | 有効時は架空データであることが画面に示され、Azure を呼び出さない。無効時は実接続を使い、失敗しても架空データを表示しない。 |

### 技術構成の候補と理由

仮実装と同じ Go + Wails v3、React + TypeScript + Vite、Azure SDK for Go、mise を起点とします。既存の画面と処理境界を検討材料にできるためです。正式採用するバージョンは U2 の確認結果で決め、仮実装の定義値を動作保証済みとしてコピーしません。

F1 では単一 Go モジュールと画面向けサービスを候補とし、独自の HTTP サーバー、DB、Repository 層、DI コンテナー、汎用状態管理は追加しません。参照対象と一覧を保持するために、これらの仕組みが必要という根拠は現時点ではありません。

| 担当・境界 | 責務と結果の確定点 | 障害時の扱い・対応シナリオ |
