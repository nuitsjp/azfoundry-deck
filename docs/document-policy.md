<a id="mock-scope"></a>
## 2. モック駆動開発の適用範囲

| 適用 | 対象 | 理由 |
| --- | --- | --- |
| 対象 | 操作対象の選択、デプロイ・モデル・クォータの表示、デプロイ変更操作、および状態（読込中・空・エラー）に関わる新規仕様や変更 | 画面表示・操作・状態遷移をモックで確認・合意したうえで実処理へ接続するため。 |
| 対象外 | 文書整備、開発・ビルド環境設定、確定済み仕様の不具合修正、振る舞いを変えない内部変更 | 画面動作による仕様合意を要しないため。文書整合性確認や個別の技術検証を行う。 |

認証、権限、Azure API との互換性、ネイティブ起動は実環境で検証します（仕様判断に必要な場合は最小限の先行技術検証が可能）。機能ごとの合意は [プロジェクト定義](project.md#features)、モック境界と技術選定は [実現方法](project.md#design) に記録します。

<a id="sources"></a>
## 3. 文書の役割と分割

| 文書 | 役割と扱う内容 |
| --- | --- |
| 本書 | 標準の採用記録、正本の配置、保護する合意 |
| `standards/` 各標準 | プロジェクト非依存の開発・文書基準 |
| [project.md](project.md) | プロジェクトの目的・制約、仕様、設計判断、手順、検証結果 |
| 外部の仮実装・検証記録 | 調査用の参考資料（[参照資料](project.md#references)）。正式版の正本ではない。 |
| [PLAN.md](../PLAN.md) | 作業進捗、作業順序、未決事項の管理 |
| [README.md](../README.md) | プロジェクト概要と参照案内 |
| [AGENTS.md](../AGENTS.md) | AIエージェントの行動指針 |

- **文書の分割基準**: 単独参照の必要性や更新頻度の違いにより管理が困難になった場合のみ正本を分割します。分割時は元の記述を参照に置き換え、本表および関連リンクを更新してください。
- **形式の柔軟性**: 図の形式や章構成は固定しません。プロジェクト固有で必須とする資料や観点がある場合は本節に記録します。

<a id="agreements"></a>
## 4. 保護する合意

採用した開発基準、適用範囲、正本の責務、および [プロジェクト定義](project.md) で合意済みの要件・制約・仕様・完了条件を保護対象とし、変更時は [標準の変更手続き](standards/design-and-documentation.md#agreement-changes) に従います。

合意内容と根拠は、[プロジェクト定義の合意事項](project.md)、[F1 のヒアリング結果](project.md#f1-agreement)、[モック用技術構成](project.md#mock-stack) に記録します。要件のヒアリング合意と、動作するモックによる仕様合意は区別します。仮実装の資産（コード・文書・デモ）や検討中の案を暗黙に合意事項とはみなさず、未確定事項は [PLAN.md](../PLAN.md) で管理します。
