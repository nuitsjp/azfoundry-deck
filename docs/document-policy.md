<a id="mock-scope"></a>
## 2. モック駆動開発の適用範囲

| 適用 | 対象 | 理由 |
| --- | --- | --- |
| 対象 | 操作対象の選択、デプロイ・モデル・クォータの表示、デプロイ変更操作、および読込中・空・エラー状態に関わる新規仕様や変更 | 画面・操作・入出力・状態遷移を、動作するモックで確認してから実処理へ接続するため。 |
| 対象外 | 今回の文書整備、開発環境・ビルド設定、確定済み仕様の不具合修正、振る舞いを変えない内部変更 | 画面の動作による仕様合意を要しないため。文書整合性確認や変更に応じた技術検証を行う。 |

認証、権限、Azure API との互換性、ネイティブ起動は実環境で検証します。モックだけではこれらの確認を完了できません。外部連携の実現性が仕様判断に必要な場合は、標準に従って最小限の技術検証を先行できます。

仮実装のデモは参照資料であり、正式版のモック合意を済ませたものとはみなしません。機能ごとの合意は [プロジェクト定義](project.md#features)、モック境界と技術選定は [実現方法](project.md#design) に記録します。

## 3. 文書の役割と分割

| 正本 | 扱う内容 |
| --- | --- |
| 本書 | 標準の採用記録、正本の配置、保護する合意 |
| `standards/` 各標準 | プロジェクト非依存の開発・文書基準 |
| [project.md](project.md) | プロジェクトの目的・制約、仕様、設計判断、手順、検証結果 |
| 外部の仮実装・検証記録 | [プロジェクト定義の参照資料](project.md#references) に列挙した調査用の証跡。正式版の仕様や検証結果の正本ではない。 |
| [PLAN.md](../PLAN.md) | 作業進捗、作業順序、未決事項の管理 |
| [README.md](../README.md) | プロジェクト概要と参照案内 |
| [AGENTS.md](../AGENTS.md) | AIエージェントの作業規則 |

- **文書の分割基準**: 単独参照の必要性や更新頻度の違いにより管理が困難になった場合のみ正本を分割します。分割時は元の記述を参照に置き換え、本表および関連リンクを更新してください。
- **形式の柔軟性**: 図の形式や章構成は固定しません。プロジェクト固有で必須とする資料や観点がある場合は本節に記録します。

<a id="agreements"></a>
## 4. 保護する合意

採用した規則、適用範囲、正本の責務、および [プロジェクト定義](project.md) で合意済みの要件・制約・仕様・完了条件を保護対象とします。これらを変更・緩和する場合は、[標準の変更手続き](standards/design-and-documentation.md#agreement-changes) に従います。

今回の依頼で確定しているのは、提供された仮実装の正式実装を本リポジトリーで行うことと、このテンプレートに従って開発することです。仮実装のコード・文書・デモの存在は、個々の製品仕様や技術選定への合意を意味しません。

検討中の案やモック上の仮定は合意済みとはみなしません。未確定事項は [PLAN.md](../PLAN.md) で管理します。
