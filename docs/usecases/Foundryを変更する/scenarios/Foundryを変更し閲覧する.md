# Foundryを変更し閲覧する

- 種別: 主成功
- UI確認: 要

## 開始条件

ログイン済みの利用者が Home画面で現在と異なる Foundry を選択する。変更先のデプロイ済みモデルを Azure から取得でき、ファイル保存が成功する。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | Foundry のプルダウンを開く。 | 保持している Foundry 一覧と現在の選択を表示する。 |
| 2 | 現在と異なる Foundry を選択する。 | プルダウンを閉じて進捗モーダルを開き、変更先のすべてのデプロイ済みモデルを Azure から取得する。 |
| 3 | モーダルで取得の進捗を確認する。 | 「Deployments」を「Loading」で表示し、変更先の名称と累積件数を表示する。全モデルの取得後に「Completed」にする。 |
| 4 | 完了した Foundry とデプロイ済みモデルを確認する。 | 変更先の選択を状態ファイルに保存する。保存成功後に画面の選択とモデルを更新し、進捗モーダルを閉じる。 |
| 5 | 選択済みの Foundry にマウスを合わせる。 | 選択表示の全文をツールチップに表示する。 |

## 受け入れ条件

- 保持している Foundry 一覧から変更先を選択できる。
- Foundry 一覧を再取得しない。
- 変更先のデプロイ済みモデルは、保存の有無にかかわらず Azure から全ページ取得する。変更前の Foundry のデプロイ済みモデルを再利用しない。
- 進捗モーダルは「Deployments」の1行だけを表示し、「Loading」「Completed」、変更先の名称、累積件数を示す。取得中の行には回転表示を付け、結果は行の右側に表示する。
- Foundry 一覧の取得の進捗を表示しない。
- 処理中は Foundry を再変更できず、閉じるボタン・Escape・モーダル外クリックで進捗モーダルを閉じない。
- 処理が完了するまで、変更前に確定した Foundry の選択とモデル表示を維持する。
- 状態ファイルには変更先の選択だけを反映し、Foundry 一覧と Foundry 一覧の最終取得日時は変更しない。デプロイ済みモデルの一覧は保存せず、`foundry-models` ディレクトリも作らない。
- モデルの取得と必要なファイル保存のすべてが成功した後に結果を確定する。
- 変更先のデプロイ済みモデルの最終取得日時は、取得が完了した時刻に更新する。
- アプリケーションを再起動した場合は、変更後の選択を復元し、その Foundry のデプロイ済みモデルを Azure から取得する。
