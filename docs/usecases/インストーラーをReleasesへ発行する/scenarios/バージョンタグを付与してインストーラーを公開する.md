# バージョンタグを付与してインストーラーを公開する

- 種別: 主成功
- UI確認: 不要

## 開始条件
- リリース対象の変更がコミット済みで、作業ツリーがクリーンである。
- 担当者がGitHubへpushでき、Windows CIが実行可能である。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | `mise run release:tag -- 0.2.0` のように実行する。バージョン指定は省略できる。 | 指定値を採用する。未指定なら `build/app.json` の末尾の数値だけを1増やす。 |
| 2 | 同じタスクの実行を継続する。 | バージョンを検証し、`build/app.json` を更新する。変更がある場合は、このファイルだけをコミットする。 |
| 3 | 同じタスクからリリースを開始する。 | 対象コミットにバージョンタグを作成し、対象コミットとタグをoriginへpushする。 |
| 4 | GitHubへバージョンタグがpushされる。 | CIがタグのコミットを取得し、タグと `build/app.json` のバージョン一致を確認して、製品側の検証・ビルド・インストーラー生成を行う。 |
| 5 | 担当者がCI結果とReleaseを確認する。 | 全工程の成功後、タグに対応するReleaseを作成し、インストーラーを添付する。公開先URLをCIに表示する。 |

## 受け入れ条件
- バージョン指定時は、その値がタグ・アプリ・インストーラーへ反映される。
- 未指定時は、例えば `0.1.0` が `0.1.1` になる。
- 指定値は現在のバージョンより大きい値に限る。
- 不正な値、作業ツリーの変更、既存タグとの重複は、ファイル変更・コミット・pushの前にエラーにする。
- 検証・ビルド・生成に失敗した場合は、Releaseを公開せずCIを失敗として終了する。
- 既存Releaseの上書きは行わない。
