# Foundry一覧の更新で選択先が変わる

- 種別: 拡張
- UI確認: 要

## 分岐条件

シナリオ「Foundry一覧を更新する」で Azure から更新後の一覧を取得した時点で、選択中の Foundry がその一覧に含まれず、参照可能な Foundry が1件以上含まれる。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | Foundry のプルダウンの右にある「Foundry一覧を更新」ボタンを押す。 | [Foundry一覧を更新する](Foundry一覧を更新する.md)の検索開始と同じ進捗モーダル、検索状態、発見件数を表示する。 |
| 2 | モーダルで一覧取得の進捗を確認する。 | 見つかったサブスクリプションを一覧へ追加し、各行に名称と「待機中」「Foundry取得中」を表示する。最大8件を並列に処理し、完了した行は一覧から削除して完了件数を更新する。 |
| 3 | モーダルでモデル取得の進捗を確認する。 | 全 Foundry の取得後、現在の選択先が一覧に含まれないことを確認し、更新後の一覧の最初の Foundry を新しい選択先として全モデルを取得する。選択先の名称、モデル取得の「取得中」「完了」と累積件数を表示する。 |
| 4 | 取得と保存の完了を確認する。 | ファイルの保存状況を表示し、新しい選択先のモデルファイルを保存する。一覧に含まれない Foundry のモデルファイルを削除した後、一覧・選択・モデル・取得日時を状態ファイルに保存する。成功後にモーダルを自動で閉じ、画面の一覧・選択・モデル・取得日時を更新する。 |
| 5 | Foundry のプルダウンを開く。 | 更新後のすべての Foundry を、各項目の全文が読める状態で表示する。 |

## 受け入れ条件

- 一覧の検索・全ページ取得と進捗表示・並列数は、[Foundry一覧を更新する](Foundry一覧を更新する.md)の受け入れ条件に従う。
- 更新後の一覧の最初の Foundry を新しい選択先とする。
- 新しい選択先のモデルファイルの有無にかかわらず、その全モデルを Azure から全ページ取得する。
- モデル取得の開始時に選択先の名称と「取得中」を表示し、取得完了時に「完了」を表示する。「待機中」は表示しない。
- モデルの取得件数を累積件数として表示する。
- ファイル保存の「待機中」「保存中」「完了」を表示する。
- 新しい選択先のモデルファイルを保存し、更新後の一覧に含まれない Foundry のモデルファイルを削除した後、最後に状態ファイルを保存する。
- 状態ファイルには、更新後の Foundry 一覧・選択・全モデルと、一覧およびモデルそれぞれの取得完了日時を保存し、画面の内容と一致させる。
- 一覧とモデルの取得、必要なファイル削除と保存のすべてが成功した後に結果を確定する。
- 保存が成功するまで、更新前の Foundry 一覧・選択・モデル表示を維持する。
- 保存成功後はモーダルを自動で閉じる。
- アプリケーションを再起動した場合も、更新後の Foundry 一覧・選択・モデル・最終取得日時を復元する。
