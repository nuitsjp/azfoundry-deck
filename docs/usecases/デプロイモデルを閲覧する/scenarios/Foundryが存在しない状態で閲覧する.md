# Foundryが存在しない状態で閲覧する

- 種別: 拡張
- UI確認: 要

## 分岐条件
ログイン済みの利用者が Home画面を表示し、保存済みの Foundry 一覧・選択済み Foundry が存在しない。Foundry 一覧の取得は成功したが、参照可能な Foundry が1件もない。ファイル保存が成功する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | ログイン済みの状態で Home画面を初めて表示する | 「Loading deployments」という進捗モーダルを開き、Foundry 一覧の取得を行う。進捗は主成功と同じ形式で表示する。 |
| 2 | モーダルで取得の進捗を確認する | Foundry 一覧の取得が完了し、Foundry が0件であることを確認する。モデルの取得は行わず、「Deployments」は「Waiting」のままにする。 |
| 3 | 取得と保存の完了を確認する | Foundry が0件であることと取得日時をファイルに保存する。保存成功後にモーダルを自動で閉じ、Foundry のプルダウンとデプロイ済みモデルの一覧を空の状態で表示する。 |

## 受け入れ条件
- 参照可能な Foundry が0件の場合を、エラーとして扱わない。`FOUNDRY_LOAD_FAILED` を表示しない。
- 進捗モーダルは、主成功と同じ形式で表示する。「Deployments」は「Waiting」のままにする。
- Foundry が0件であること、Foundry 一覧の最終取得日時を状態ファイルに保存し、画面の内容と一致させる。状態ファイルにデプロイ済みモデルの一覧は含めず、`foundry-models` ディレクトリも作らない。
- Foundry のプルダウンは選択なしで選択肢を持たず、デプロイ済みモデルの一覧は0件の空の状態で表示する。「Refresh models」ボタンは無効にする。
- 「Refresh Foundries」ボタンと Foundry 一覧の最終取得日時は通常どおり表示する。
- アプリケーションを再起動した場合は、保存済みの状態から同じ表示にし、Azure から取得し直さない。選択済み Foundry がないため、デプロイ済みモデルの取得も行わない。
