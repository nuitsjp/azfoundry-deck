# 起動時に取得した新版で更新して再起動する

- 種別: 主成功
- UI確認: 要

## 開始条件
GitHub Releases の最新リリースが実行中のアプリ（例: v0.1.3）より新しい版（例: v0.2.0）である状態で、利用者がアプリを起動する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者がアプリを起動する | 通常どおり Home画面を表示する。起動処理とは別にバックグラウンドで、最新リリースの `update.json` を取得して署名を検証する。実行中の版より新しいので、インストーラーを取得してサイズとハッシュを検証し、アプリのデータフォルダーに置く |
| 2 | インストーラーの取得と検証が終わる | Home画面の先頭に更新の区画を表示する。区画には `バージョン 0.2.0 の準備ができました。` と `更新して再起動` ボタンを表示する |
| 3 | 利用者が `更新して再起動` を押す | 置いたインストーラーのサイズとハッシュを検証し直す。インストーラーを画面なしで起動して引き渡し、アプリを終了する |
| 4 | インストーラーがアプリの終了を確認する | アプリのファイルとアンインストール情報を更新し、新版のアプリを起動する |
| 5 | 利用者が起動した新版のアプリを確認する | ログイン済みの状態で Home画面を表示する。更新の区画は表示しない |

## 受け入れ条件
- 新版の確認は起動時に1回だけ行う。確認と取得は自動で行い、適用（インストールと再起動）は利用者が `更新して再起動` を押したときだけ行う。
- 最新リリースが実行中の版と同じか古い場合、更新の区画は表示しない。
- 確認・取得・検証が失敗した場合（通信できない、リリースがない、署名やハッシュが一致しない）は、更新の区画を表示せず、ログに原因の分類だけを書く。取得途中のファイルは削除する。再確認は次の起動時に行う。
- 手順3の再検証が失敗した場合は、アプリを終了せず、更新の区画に `更新を検証できませんでした。次回の起動時に確認し直します。` を表示する。
- 起動したインストーラーの画面は表示しない（サイレント実行）。
- 開発時の起動（`mise run dev`）とブラウザー確認用サーバーでは、新版を確認しない。
