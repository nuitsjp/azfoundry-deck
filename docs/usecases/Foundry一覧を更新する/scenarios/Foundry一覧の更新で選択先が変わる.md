# Foundry一覧の更新で選択先が変わる

- 種別: 拡張
- UI確認: 要

## 分岐条件

シナリオ「Foundry一覧を更新する」で Azure から更新後の一覧を取得した時点で、選択中の Foundry がその一覧に含まれず、参照可能な Foundry が1件以上含まれる。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | Foundry のプルダウンの右にある「Refresh Foundries」ボタンを押す。 | [Foundry一覧を更新する](Foundry一覧を更新する.md)の開始時と同じ進捗モーダルを開き、「Foundries」を「Loading」、「Deployments」を「Waiting」で表示する。 |
| 2 | モーダルで一覧取得の進捗を確認する。 | Foundry 一覧の取得後、「Foundries」を「Completed」と取得した Foundry の件数で表示する。 |
| 3 | モーダルでモデル取得の進捗を確認する。 | 全 Foundry の取得後、現在の選択先が一覧に含まれないことを確認し、更新後の一覧の最初の Foundry を新しい選択先として全モデルを Azure から取得する。「Deployments」を「Loading」にし、選択先の名称と累積件数を表示する。 |
| 4 | 取得と保存の完了を確認する。 | 「Deployments」を「Completed」にし、取得したモデルと取得日時をメモリに保持する。Foundry 一覧・選択・Foundry 一覧の取得日時を状態ファイルに保存する。成功後にモーダルを自動で閉じ、画面の一覧・選択・モデル・取得日時を更新する。 |
| 5 | Foundry のプルダウンを開く。 | 更新後のすべての Foundry を、各項目の全文が読める状態で表示する。 |

## 受け入れ条件

- 一覧の全ページ取得と進捗表示は、[Foundry一覧を更新する](Foundry一覧を更新する.md)の受け入れ条件に従う。
- 更新後の一覧の最初の Foundry を新しい選択先とする。
- 新しい選択先の全モデルを Azure から全ページ取得する。
- 一覧の取得が完了するまで「Deployments」は「Waiting」とし、モデル取得の開始時に「Loading」と選択先の名称を表示し、取得完了時に「Completed」を表示する。
- モデルの取得件数を累積件数として表示する。
- 状態ファイルには、更新後の Foundry 一覧・選択・Foundry 一覧の取得完了日時だけを保存し、画面の内容と一致させる。デプロイ済みモデルとその取得日時は保存せず、メモリにだけ保持する。
- 一覧とモデルの取得と保存のすべてが成功した後に結果を確定する。
- 保存が成功するまで、更新前の Foundry 一覧・選択・モデル表示を維持する。
- 保存成功後はモーダルを自動で閉じる。
- アプリケーションを再起動した場合の復元は、[Foundry一覧を更新する](Foundry一覧を更新する.md)の受け入れ条件に従う。
