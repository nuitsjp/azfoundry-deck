# 新規デプロイモデルを追加する

- 種別: 主成功
- UI確認: 要

## 開始条件

ログイン済みの利用者が、Foundry 一覧とデプロイ済みモデルを表示した Home画面で、「Add deployment」ボタンを押す。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | デプロイ済みモデル一覧の見出し右にある「Add deployment」ボタンを押す。 | デプロイ作成モーダルを開き、選択中 Foundry の保持済みモデル定義からカタログを表示する。モデル定義が取得中の場合だけプログレスを表示して同じ取得の完了を待つ。左側にモデル検索・フィルター（Publisher、Deployment option、Tasks）とモデル一覧、右側にデプロイ設定入力欄を表示する。初期状態で先頭のモデルを選択し、Deployment name にそのモデル名を初期設定する。容量上限は保持済みの共有クォータから表示し、クォータが取得・更新中なら上限を Loading... として、完了後に確定する。 |
| 2 | 左側で追加したいモデルを選び、必要に応じて右側で設定（Deployment name、Version、SKU、Capacity 等）を調整して「Deploy」を押す。 | デプロイ作成モーダルを開いたまま、その前面に進捗モーダル（Step: Deploy）を重ねて表示し、Azure にデプロイ作成を依頼して完了まで待つ。 |
| 3 | 作成完了後のデプロイ済みモデルを確認する。 | 作成完了後に選択中 Foundry のデプロイ済みモデルを Azure から取得し直してメモリに保持し、進捗モーダルとデプロイ作成モーダルの両方を閉じる。モデル一覧・件数・最終取得日時を更新し、新規追加されたモデルを表示する。モデル定義を保持したまま共有クォータだけをバックグラウンドで更新し、以降の追加に更新結果を使う。 |

## 受け入れ条件

- モーダルで「Cancel」または「×」を押した場合は、リソースを変更せず、作成前のデプロイ一覧を維持する。
- モデル定義と共有クォータが取得済みの場合、追加画面の開閉では Azure を呼ばず、固定時間の読み込み表示を挟まずにカタログと設定欄を表示する。取得・更新中の情報は、開始済みの処理の完了を共有し、同じ情報を重複して取得しない。
- モデル定義は利用中の同じ Foundry で再利用し、新しいモデルやバージョンを調べるための定期取得は行わない。保持状態の識別・破棄とクォータの更新条件は [モデルカタログと共有クォータの保持](../../../design/UCP-1.md#モデルカタログと共有クォータの保持) に従う。
- Foundry、テナントまたはログイン中のアカウントが変わった場合、前の対象のカタログ、検索・フィルター、選択モデル、Deployment name、Version、SKU、Capacity を破棄する。変更前に開始した取得が後から完了しても、変更後の画面へ反映しない。
- モデル選択時、右ペインの Deployment name には選択したモデル名がデフォルトで自動入力され、テキストボックスで直接編集できる。
- モデルカタログの Publisher、Deployment option、Tasks（Chat, Reasoning, Embeddings, Multimodal 等）のフィルターでモデル一覧をリアルタイムに絞り込める。
- Standard モデル選択時は Capacity の割り当て可能上限（利用可能クォータ）を明示し、詳細画面と揃えた形式と単位（`現在値 / 最大値 単位`。TPM、RPM、PTU）で表示する。初期値は上限の 50% を刻みに合わせて切り下げた値とし、数値テキストボックスでの直接入力とスライダーの両方で、モデル・SKUの設定の最小値と刻みに合わせて調整でき、双方が連動する。設定に最小値と刻みが無い場合は、SKUの容量1単位分（TPM のモデルでは通常 1,000、RPM のモデルでは 1）を最小値と刻みとする。単位を求められない SKU は Capacity を入力できず、Deploy を無効にする。
- Standard のクォータが取得・更新中の場合は容量上限を Loading... とし、Capacity の入力と Deploy を無効にする。モデル一覧の表示とモデル選択は受け付ける。取得完了時に上限を表示し、まだ入力を始めていないモデルの Capacity を上限の 50% に初期設定する。入力済みの値は更新で書き換えず、上限を超える値の場合は上限以内に修正するまで Deploy を無効にする。
- クォータの取得・更新に失敗した場合は原因を表示し、古い値を上限として使用せず、Standard の Deploy を無効にする。更新失敗によって、完了済みのデプロイ作成を失敗として扱わない。
- Pay-as-you-go モデル選択時は TPM クォータ入力を行わず、従量課金レート情報を表示する。
- 必須項目（Deployment name 等）の未入力または不正値がある場合は作成を実行できない。
- デプロイ実行時は確認ダイアログを表示せず、デプロイ作成モーダルの前面に進捗モーダル（Step: Deploy）を表示する。進捗モーダルは Escape や外側クリックで閉じない。
- デプロイの完了後は、作成前の一覧への手動追加ではなく、Azure から取得し直した結果で選択中 Foundry の表示を置き換える。デプロイ済みモデルは保存せず、状態ファイルの内容は変えない。
- 別の Foundry へ変更して戻った場合や画面を再読み込みした場合も、Azure から取得し直した追加後のモデル一覧を表示する。
