# 一覧からデプロイモデルの明細を表示する

- 種別: 主成功
- UI確認: 要

## 開始条件

Home画面に選択中の Foundry のモデル一覧が表示され、対象モデルが1件以上存在する。取得・更新・切り替え処理は実行中でない。

## 手順

| # | アクター | システム |
| --- | --- | --- |
| 1 | 左側の一覧で対象デプロイの行を押す。 | 行を選択状態にし、以前の明細を消す。右側の `Details` に `Loading...` と回転表示を出して対象モデルの明細を Azure から取得する。 |
| 2 | 取得された明細を確認する。 | 取得成功後、右側にデプロイ名、明細項目、取得日時を表示する。左の一覧と Foundry の選択は維持する。 |
| 3 | 同じデプロイの行または別のデプロイの行を押す。 | キャッシュを利用せず、指定したデプロイの明細を再取得して表示する。 |

## 受け入れ条件

- Home画面のモデル領域を一つの外枠で囲み、左右同じ幅で、左に一覧、右に明細を表示する。中央に境界線を置き、同じ高さの見出しを左は `Deployments`、右は `Details` とする。
- 外枠の見出しは `Deployed Models` とする。一覧は `Deployment`、`Model`、`Version` の3列とし、選択行を青で強調する。
- 一覧は行のどこを押しても選択できる。デプロイ名はキーボードでも操作できるボタンとする。初期表示ではモデルを選択せず、右側の明細内容は空とする。
- 画面内の項目名・操作名・状態は英語で表示し、操作方法の補足説明は表示しない。
- 明細の見出しにデプロイ名を表示する。項目表に `Model`、`Version`、`SKU`、`Capacity`、`Provisioning state`、`Upgrade policy` を表示する。
- `Capacity` は設定済み容量と、共有クォータの残量を踏まえた割り当て可能上限を `現在値 / 上限 単位` の形式で表示する。上限は現在の割り当てに同じサブスクリプション・リージョン・モデル・デプロイ種別の共有クォータ残量を加えた値と、モデル・SKUの設定上限の小さい方とする。Standard 系は TPM、Provisioned 系は PTU とし、Standard の換算はモデルごとの定義に従う。値には桁区切りを付け、`0` はそのまま表示する。取得できない値は `Not set` とし、上限を推測で補わない。
- `Upgrade policy` の表示名は `OnceNewDefaultVersionAvailable` を `Upgrade to new default`、`OnceCurrentVersionExpired` を `Upgrade on retirement`、`NoAutoUpgrade` を `No automatic upgrade` とする。内部値は変更しない。未設定は `Not set`、未知の値は内部値をそのまま表示する。その他の値が返されない項目も `Not set` と表示する。
- 明細の取得が完了した時刻を、`Last fetched` とローカル時刻の `YYYY-MM-DD HH:mm` 形式で表示する。一覧と明細の取得日時は別々に表示する。
- 明細は選択のたびに Azure から取得する。同じデプロイを選んだ場合も取得する。表示中の結果だけを保持し、再利用するキャッシュやファイル保存は行わない。
- 明細の取得に伴い、既存の Foundry 一覧・モデル保存ファイルは変更しない。
- 取得中は古い明細を表示せず、追加のモデル選択・テナント変更・Foundry 変更・一覧とモデルの更新を受け付けない。表示後はこれらの操作を受け付ける。
- Foundry またはテナントが変わる場合は明細の選択と表示を破棄し、変更前の明細を表示しない。一覧が更新された場合も明細を破棄する。
- 取得に失敗した場合は右側に `DEPLOYMENT_DETAIL_FAILED` と理由、および `Retry` を表示する。失敗時にも左の一覧を維持する。再試行時は明細を取得し直す。
