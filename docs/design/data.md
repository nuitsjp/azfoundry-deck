# データ設計

保存形式と現在のテーブル設計の正本です。DBを使う場合は以下にER図とテーブル定義を記載し、使わない場合はその旨と実際の保存形式を記します。変更範囲と論点は [設計標準](../standards/design-and-documentation.md#architecture-method) に従って会話で提示します。

DB は使いません。アカウント識別情報は OS のクレデンシャルマネージャーに、トークンは Azure SDK の永続キャッシュに保存し、ログイン状態はメモリで保持します。

## ログイン情報と選択テナント

Windows 資格情報マネージャーの汎用資格情報 `AzFoundryDeck:AuthenticationRecord` に、アカウント識別情報・テナント一覧・選択テナントを一つの JSON として保存します。SDK の `AuthenticationRecord` の JSON 項目は維持し、同じ階層に次の項目を追加します。パスワードとトークンは含めません。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `tenants` | 配列 | ブラウザーでのサインイン時に ARM から取得したテナント一覧 |
| `tenants[].id` | 文字列 | テナント ID |
| `tenants[].displayName` | 文字列 | テナントの表示名 |
| `selectedTenantId` | 文字列 | ARM の一覧から選んだ利用対象テナントの ID。選択前は空文字列 |

認証完了後に認証記録と空の選択を保存し、ARM の一覧取得後に一覧の ID・表示名と唯一の候補の ID を含めて同じ資格情報を更新します。選択の保存が成功した時点で閲覧可能な状態を確定します。一覧取得や選択保存に失敗した場合は、認証記録を保持し、閲覧を開始しません。通常起動時とテナント変更時は保存済みの一覧を使い、ARM の一覧を取得し直しません。再サインイン時に一覧を取得し直し、保存内容を更新します。

SDK の認証記録にある `tenantId` は認証記録の一部として保持しますが、利用対象テナントの照合・選択には使用しません。読み出し時に認証記録・`tenants`・`selectedTenantId` をそれぞれ復号します。ログアウトでは、この資格情報全体を削除します。

### 閲覧データの保存範囲

Foundry 一覧と選択の保存先は、アカウントと選択テナントの組み合わせで分離します。アプリのデータフォルダーの `azure-views/<識別値>/` を、以下の Foundry 保存形式の基準フォルダーとします。識別値は、認証記録の `homeAccountId` と `selectedTenantId` をこの順の JSON 文字列配列として UTF-8 で表現し、SHA-256 でハッシュ化した小文字の16進数です。

選択済みテナントがない場合は閲覧データを読み書きしません。従来のデータフォルダー直下にある閲覧ファイルは移行・読み込みを行わず、新しい保存先で Foundry 一覧を取得します。

### ログアウト時の削除範囲

ログアウトでは、このアプリの資格情報全体と永続トークンキャッシュ（`azfoundrydeck`、`azfoundrydeck.cae`）、データフォルダーの `azure-views/` 以下にあるすべてのアカウント・テナントの閲覧保存データを削除します。従来のデータフォルダー直下の `foundry-state.json` と、以前のアプリが作った `foundry-models/`（古い保存データの掃除）も削除します。メモリ上の認証・テナント・閲覧状態も破棄します。診断ログとアプリ設定は削除対象に含めません。他のアプリの認証情報・トークンには触れません。

## Foundry とデプロイモデル

閲覧データの基準フォルダーに `foundry-state.json` を UTF-8 の JSON で保存します。アプリのデータフォルダーの既定値は `%APPDATA%\AzFoundryDeck` です。`WAILS_DATA_DIR` を指定した場合はそのフォルダーを使います。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `foundries` | 配列 | 取得したすべての Foundry |
| `foundries[].id` | 文字列 | Foundry の Azure リソース ID |
| `foundries[].name` | 文字列 | Foundry の名称 |
| `foundries[].subscriptionName` | 文字列 | 所属サブスクリプション名 |
| `foundries[].resourceGroupName` | 文字列 | 所属リソースグループ名 |
| `selectedFoundryId` | 文字列 | `foundries[].id` のいずれかを参照する選択済み Foundry。`foundries` が空の場合は空文字列 |
| `foundriesFetchedAt` | 文字列 | Foundry 一覧の取得が完了した時刻（RFC 3339、ローカル時刻のオフセットと秒を含む） |

保存するのは Foundry 一覧、選択、一覧の取得日時だけで、すべての項目は必須です。参照可能な Foundry が0件の場合は、`foundries` を空配列、`selectedFoundryId` を空文字列として保存します。認証情報やトークンは保存しません。以前のアプリが保存した `deployments` などの余分な項目は読み込み時に無視し、互換のための変換はしません。

Home画面で保存済みファイルが存在しない場合は、Azure から Foundry 一覧を取得して保存します。保存済みファイルが存在して読み込みに成功した場合は、Foundry 一覧と選択を復元し、Foundry 一覧を取得し直しません。読み込みや JSON の復元に失敗した場合は `FOUNDRY_LOAD_FAILED` で停止し、取得へのフォールバックを行いません。

### デプロイ一覧と容量上限

デプロイ一覧はファイルに保存せず、Go サービスのメモリに保持します。メモリに持つのは、選択中の Foundry のデプロイ一覧（各デプロイの SKU 名・容量・容量単位・状態・更新ポリシーを含む）とその取得日時です。アプリ起動時（ログイン済みの復元後）、Foundry の変更、テナントの変更、デプロイモデルの更新、デプロイの追加・変更・削除の成功後、選択先が変わる Foundry 一覧の更新の後に Azure から取得し、取得完了の時刻を `deploymentsFetchedAt` として画面へ返します。取得に失敗した場合は正常な閲覧結果を返しません。

容量上限の計算に使うモデル定義一覧と共有クォータ一覧も、Foundry ごとにメモリだけで保持し、ファイルに保存しません。画面の読み込み、Foundry の変更、テナントの変更、ログアウトで破棄します。

`foundriesFetchedAt` は Foundry 一覧の取得が完了した時刻で、Foundry 一覧の取得時だけ更新します。

状態ファイルは同じフォルダーの一時ファイルへ書き込み、同期とクローズを完了した後に目的のファイルを置き換えます。保存に失敗した場合は正常な閲覧結果を返しません。
